## What this is

`ddplot` is an R package that wraps [r2d3](https://rstudio.github.io/r2d3/) to expose D3.js SVG charts via a simple R API. Each chart type has two files: an R function in `R/` and a corresponding D3 JavaScript file in `inst/d3/scatterplot/` (all JS lives in that one directory despite the misleading name).

## Architecture

- **`R/*.R`** — One file per chart type. Each exports a single function (e.g. `bar_chart()`, `line_chart()`). Functions validate inputs then call `r2d3::r2d3()`, passing the data frame and an `options` list to the corresponding JS file.
- **`inst/d3/scatterplot/*.js`** — D3.js scripts, one per chart type. They receive `data`, `width`, `height`, and `options` from r2d3 and render an SVG. All JS files live in this one directory regardless of chart type.
- **`man/`** — Auto-generated by roxygen2 from `@param`/`@return`/`@examples` tags. Never edit manually.
- **`NAMESPACE`** — Auto-generated by `devtools::document()`. Never edit manually.

## Adding a new chart type

1. Create `R/newchart.R` with a roxygen2-documented exported function that calls `r2d3::r2d3()`.
2. Create `inst/d3/scatterplot/newchart.js` with the D3 rendering logic.
3. Point the R function's `script` argument to `system.file("d3/scatterplot/newchart.js", package = "ddplot")`.
4. Run `devtools::document()` to update `NAMESPACE` and `man/`.

## Naming conventions

Function names use `snake_case` (e.g. `bar_chart`, `pulse_grid`). The corresponding JS files use lowercase with no separators (e.g. `barchart.js`, `pulsegrid.js`). Some older R source files still use camelCase filenames — new files should use snake_case for the R file.
